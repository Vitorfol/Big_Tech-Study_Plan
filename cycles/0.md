## 1. Cycle Goal

Cycle 0 is not a maximum-intensity cycle.

The goal is to:
1. validate the quarter system;
2. build the tracking habit;
3. start using Grind 75 consistently;
4. use CIU by topic without turning it into an infinite reading queue;
5. diagnose real Coding/DS gaps;
6. start System Design with reading and guided questions before full design;
7. keep Mock/Career light but present;
8. prepare Cycle 1 with real data.

The main success criterion is not raw volume. The main success criterion is that the system becomes executable, measurable, and easy to adjust.

## 3. Topic Rationale

The topics in Cycle 0 were selected to avoid random study.

```text
Week 0:
- refresh high-frequency coding patterns;
- validate the study system;
- establish the baseline;
- test the System Design reading/guided-questions flow.

Week 1:
- attack a known weaker area: Trees / DFS / BFS;
- rebuild traversal fluency in C++.

Week 2:
- extend traversal reasoning from Trees to Graphs and Matrices;
- reinforce visited logic and graph representation.

Week 3:
- consolidate the weakest topic from Weeks 0–2;
- shift from topic isolation to mixed recognition;
- produce the first System Design mini design.
```

The topic list is aligned with common interview patterns:

```text
- Arrays & Hashing
- Sliding Window
- Two Pointers
- Trees / DFS / BFS
- Binary Search
- Dynamic Programming
- Graphs
```

Dynamic Programming is intentionally not a main topic in Cycle 0. It should enter after the system is already running and traversal topics have been calibrated.

---

## 4. List Progression Rule

Grind 75 is the main list for general progression.

The weekly topic gives depth. Grind 75 gives breadth and mixed recognition.

### Target

Within the Coding/DS quarters, aim for roughly:

```text
40–50% List Progression
50–60% Topic Study / Topic Practice / Review / Performance
```

A quarter counts as `List Progression` when:

```text
- it advances the next useful Grind 75 problem; or
- it solves a Grind 75 problem aligned with the weekly topic.
```

This means a quarter can be both topic-aligned and list-driven.

Example:

```text
Topic: Trees / DFS / BFS
Problem source: Grind 75
Mode: Topic Practice + List Progression
```

### Priority Rule

```text
If Grind 75 has a problem related to the weekly topic:
- prioritize it.

If not:
- solve the next useful Grind 75 problem as mixed practice.
```

Do not use random LeetCode Daily Challenges as the main path in Cycle 0.
